# MockGatehub HTTPS Integration Plan - COMPLETE ✅

## Executive Summary

**Problem**: Browser blocked Gatehub iframe due to mixed content (HTTPS page trying to load HTTP iframe)

**Root Cause**: MockGatehub was exposed on `http://mockgatehub:8080` without HTTPS

**Solution**: Use Traefik reverse proxy to serve MockGatehub via HTTPS at `https://mockgatehub.interledger.test`

**Status**: ✅ All configuration changes completed

## Solution Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│  Browser/Frontend (https://interledger.test)                    │
│                                                                 │
│  "I need the KYC iframe from mockgatehub"                       │
│  → Gets URL: https://mockgatehub.interledger.test/?bearer=token│
│  → Browser makes HTTPS request (because whole page is HTTPS)    │
└────────────────────────────────┬────────────────────────────────┘
                                 │
                                 │ HTTPS request
                                 │ Host: mockgatehub.interledger.test
                                 │ Port: 443 (default for HTTPS)
                                 │
                   ┌─────────────▼──────────┐
                   │  /etc/hosts Lookup     │
                   │                        │
                   │ 127.0.0.1              │
                   │ mockgatehub.           │
                   │ interledger.test       │
                   └─────────────┬──────────┘
                                 │
                                 │ Resolves to 127.0.0.1:443
                                 │
                   ┌─────────────▼──────────────────────────┐
                   │  Traefik Container                     │
                   │  (Listening on 0.0.0.0:443 / HTTPS)    │
                   │                                        │
                   │  • TLS termination                     │
                   │  • Uses config/certs/local.crt         │
                   │  • Checks Host header                  │
                   │  • Routes by hostname                  │
                   └─────────────┬──────────────────────────┘
                                 │
                                 │ HTTP to Docker internal network
                                 │ Host: mockgatehub
                                 │ Port: 8080
                                 │
                   ┌─────────────▼──────────────────────────┐
                   │  MockGatehub Container                 │
                   │  (Listening on 0.0.0.0:8080 / HTTP)    │
                   │                                        │
                   │  • Responds with iframe HTML           │
                   │  • Handles KYC iframe POST requests    │
                   │  • Sends webhooks to backend           │
                   └─────────────┬──────────────────────────┘
                                 │
                                 │ Response flows back through
                                 │ Traefik (wrapped in HTTPS)
                                 │
                   ┌─────────────▼──────────────────────────┐
                   │  Browser Receives HTTPS Response       │
                   │                                        │
                   │  ✅ Content-Type: application/json     │
                   │  ✅ Connection: HTTPS                  │
                   │  ✅ No mixed content errors!           │
                   └────────────────────────────────────────┘
```

**Separate path for backend service** (doesn't go through browser):
```
Backend Container (Go)
       │
       │ Calls: http://mockgatehub:8080/id/v1/users (API call)
       │
       ├─ Docker DNS resolves "mockgatehub" to container IP
       │
       └─ Fast HTTP connection (same Docker network, no TLS overhead)
```

## Changes Made ✅

### 1. `/local/Makefile` ✅
**Added to `hosts` target**:
```makefile
@echo "127.0.0.1 mockgatehub.interledger.test      # generated by make hosts" | sudo tee -a /etc/hosts > /dev/null
```

**Effect**: `make hosts` now adds `127.0.0.1 mockgatehub.interledger.test` to `/etc/hosts`

---

### 2. `/local/config/san.cnf` ✅
**Added to `[ alt_names ]` section**:
```ini
DNS.9 = mockgatehub.interledger.test
```

**Effect**: Certificate now includes `mockgatehub.interledger.test` in Subject Alternative Names
- Note: Already covered by wildcard `DNS.2 = *.interledger.test`, but explicit entry ensures compatibility

---

### 3. `/local/mockgatehub.yaml` ✅
**Changed service configuration**:

```yaml
# BEFORE:
ports:
  - "38080:8080"  # Exposed on host port 38080

# AFTER:
expose:
  - "8080"  # Internal only

labels:
  - "traefik.enable=true"
  - "traefik.http.routers.mockgatehub.rule=Host(`mockgatehub.interledger.test`)"
  - "traefik.http.routers.mockgatehub.entrypoints=websecure"
  - "traefik.http.services.mockgatehub.loadbalancer.server.port=8080"
```

**Effect**: 
- MockGatehub no longer exposed directly on port 38080
- Traefik discovers and routes all HTTPS requests to `mockgatehub.interledger.test` to port 8080 internally

## How It Solves the Mixed Content Problem

| Layer | Before | After | Why |
|-------|--------|-------|-----|
| **Browser** | Gets iframe URL: `http://mockgatehub:8080` | Gets iframe URL: `https://mockgatehub.interledger.test` | Scheme matches (HTTPS) |
| **DNS** | N/A (used port) | Looks up `mockgatehub.interledger.test` → `127.0.0.1` | Hostname resolution works |
| **Port** | Direct to port 38080 | Through port 443 (Traefik) | HTTPS default port |
| **Security** | ❌ HTTP mixed with HTTPS → blocked | ✅ HTTPS with HTTPS → allowed | Browsers allow it |

## Important: Dual-URL Pattern

This design maintains TWO different ways to access MockGatehub:

### **From Backend Services** (within Docker network)
```
GATEHUB_API_BASE_URL=http://mockgatehub:8080
```
- Uses: Docker service DNS name
- Protocol: HTTP (no cert validation)
- Performance: Fast (same Docker network)
- Use case: Backend API calls

### **From Browser Clients** (external)
```
https://mockgatehub.interledger.test/?bearer=token
```
- Uses: Hostname with domain
- Protocol: HTTPS (secure)
- Performance: Through Traefik reverse proxy
- Use case: Iframe rendering, webhook callback URLs

This is a **feature, not a bug**. It's the standard pattern for production systems:
- Services communicate via internal IPs/DNS (no HTTPS overhead)
- Clients access via HTTPS (security)
- Reverse proxy handles the bridge

## FAQ

### Q: Why two different URLs?
**A**: Docker internal networking is fast and doesn't need HTTPS. Browsers require HTTPS. Traefik bridges both worlds.

### Q: Do I need to change backend code?
**A**: No! Backend already uses `http://mockgatehub:8080`. That doesn't change.

### Q: Will this work in production?
**A**: No. This setup is local-only using self-signed certs. Production would use:
- Proper CA-signed certificates
- AWS ALB or similar load balancer instead of Traefik
- Separate DNS entries pointing to load balancer IPs

### Q: What if I change mockgatehub code?
**A**: Just rebuild: `docker compose up --build mockgatehub`

### Q: What if certificate needs refreshing?
**A**: Run `make certs` and restart services.

### Q: Can I access mockgatehub on different port?
**A**: Not directly anymore (we removed port 38080 mapping). Must go through Traefik on port 443.
You can add back the port mapping if needed for direct access, but HTTPS from browser requires Traefik.

## Troubleshooting

### Still seeing "Mixed Content" error?
1. Clear browser cache: Cmd+Shift+Delete (Chrome) or Cmd+Shift+Backspace (Safari)
2. Hard reload: Cmd+Shift+R (macOS) or Ctrl+Shift+R (Linux)
3. Check browser console (F12) for actual error message
4. Verify Traefik is actually routing: `docker compose logs traefik | grep mockgatehub`

### Certificate warnings in browser?
- macOS: Run `make trust` to add to Keychain
- Linux: Expected for self-signed certs, browser will warn until you add exception
- Firefox: Settings → Privacy → Certificates → View Certificates → Add Exception

### Can't connect to mockgatehub.interledger.test?
1. Verify /etc/hosts: `cat /etc/hosts | grep mockgatehub`
2. Verify DNS resolution: `nslookup mockgatehub.interledger.test` (should resolve to 127.0.0.1)
3. Verify Traefik is running: `docker ps | grep traefik`
4. Check Traefik logs: `docker compose logs traefik | tail -50`
5. Check port 443 is listening: `lsof -i :443` (should show traefik)

### Backend can't reach mockgatehub?
1. Verify Docker DNS: `docker compose exec backend cat /etc/resolv.conf`
2. Test from inside container: `docker compose exec backend curl http://mockgatehub:8080/health`
3. Check mockgatehub container is running: `docker ps | grep mockgatehub`
4. Check port 8080 is exposed: `docker compose exec mockgatehub netstat -tuln | grep 8080`

### Traefik shows unhealthy mockgatehub?
1. Check mockgatehub logs: `docker compose logs mockgatehub | tail -50`
2. Verify health check: `docker compose exec mockgatehub curl http://localhost:8080/health`
3. Restart mockgatehub: `docker compose restart mockgatehub`
