# MockGatehub HTTPS Integration - Summary

## Problem Statement
The browser was blocking the Gatehub iframe with a mixed content error:
- Frontend: `https://interledger.test` (secure)
- Iframe: `http://mockgatehub:8080` (insecure)
- Error: "Mixed Content: The page was loaded over HTTPS, but requested an insecure frame"

Browsers block this for security reasons - HTTPS pages cannot load HTTP iframes.

## Solution: Use Traefik HTTPS Reverse Proxy

Your instinct was correct! We're using:
1. **HTTPS endpoint**: `https://mockgatehub.interledger.test`
2. **Traefik reverse proxy**: Terminates TLS and routes to internal service
3. **Self-signed certificate**: Already exists with wildcard support
4. **DNS resolution**: Via updated `/etc/hosts`

## Files Changed

### 1. `/local/Makefile`
**Change**: Added `mockgatehub.interledger.test` to the `hosts` target
```makefile
@echo "127.0.0.1 mockgatehub.interledger.test      # generated by make hosts" | sudo tee -a /etc/hosts > /dev/null
```
**Effect**: When you run `make hosts`, it adds the local DNS mapping

### 2. `/local/config/san.cnf`
**Change**: Added explicit SAN entry
```ini
DNS.9 = mockgatehub.interledger.test
```
**Effect**: Certificate now explicitly includes mockgatehub.interledger.test (wildcard already covered it, but this ensures it)

### 3. `/local/mockgatehub.yaml`
**Changes**:
- Removed: `ports: ["38080:8080"]` (external port mapping)
- Added: `expose: ["8080"]` (Docker internal only)
- Added Traefik labels for routing:
  ```yaml
  labels:
    - "traefik.enable=true"
    - "traefik.http.routers.mockgatehub.rule=Host(`mockgatehub.interledger.test`)"
    - "traefik.http.routers.mockgatehub.entrypoints=websecure"
    - "traefik.http.services.mockgatehub.loadbalancer.server.port=8080"
  ```

**Effect**: Traefik now handles HTTPS routing and TLS termination for mockgatehub

## How Backend & Browser Access MockGatehub

### Backend Service (Go API)
```
GATEHUB_API_BASE_URL=http://mockgatehub:8080
              ↓
Internal Docker DNS resolves "mockgatehub" to container IP
              ↓
HTTP connection on internal Docker network (no HTTPS overhead)
              ↓
Fast service-to-service communication
```

### Browser/Frontend
```
Backend returns to browser:
  Widget URL: https://mockgatehub.interledger.test/?bearer=token
              ↓
Browser makes HTTPS request
              ↓
127.0.0.1 mockgatehub.interledger.test (from /etc/hosts)
              ↓
Localhost:443 (Traefik listening on port 443)
              ↓
Traefik terminates TLS using config/certs/local.crt
              ↓
Traefik forwards HTTP to mockgatehub:8080 (internal)
              ↓
Response returned via HTTPS
```

## Key Insight: Dual-URL Pattern

This setup demonstrates an important architecture pattern:

| Perspective | URL | Protocol | Use Case |
|---|---|---|---|
| **Backend/Service** | `http://mockgatehub:8080` | HTTP | Fast inter-service, no TLS overhead |
| **Browser/Client** | `https://mockgatehub.interledger.test` | HTTPS | Secure external access, browser requirements |

The same service is accessible via both URLs depending on the caller's context.

## Setup Steps

### Regenerate Certificates (includes new SAN)
```bash
cd local
make certs
```

### Update /etc/hosts
```bash
make hosts  # requires sudo
```

### Trust Certificate (macOS only)
```bash
make trust  # optional, suppresses browser warnings
```

### Restart Services
```bash
make down
make infrastructure  # Traefik + Postgres + Redis
make application     # in another terminal: all apps including mockgatehub
```

### Verify
```bash
# Check HTTPS endpoint works
curl -k https://mockgatehub.interledger.test/health

# Check Traefik routing
curl -k -H "Host: mockgatehub.interledger.test" https://localhost/health

# Browser: navigate to https://interledger.test → trigger KYC → no mixed content error!
```

## Why This Approach

### Advantages ✓
- **Secure**: Browser gets HTTPS, no mixed content errors
- **Simple**: Uses existing Traefik infrastructure
- **Fast**: Backend uses internal HTTP (no certificate overhead)
- **Consistent**: Same certificate management as other services
- **Scalable**: Traefik handles load balancing if needed

### Alternative Approaches Considered ✗

1. **HTTP for both**: ❌ Browsers block, not an option
2. **HTTPS certificates in mockgatehub**: ❌ Duplicates cert management, adds container complexity
3. **Docker hostname instead of DNS**: ❌ Can't use hostnames in browser URLs, only in code
4. **Environment-specific URLs**: ❌ Adds configuration complexity, this approach is cleaner

## Troubleshooting

### Mixed Content Still Appearing?
1. Clear browser cache: `Cmd+Shift+Delete` (Chrome/Safari)
2. Hard reload: `Cmd+Shift+R` (macOS) or `Ctrl+Shift+R` (Linux)
3. Check browser console for actual error URL

### Certificate Warnings?
- macOS: Run `make trust` to add to Keychain
- Linux: Browser warnings are expected for self-signed certs
- Firefox: Add exception in certificate manager

### Can't Connect to mockgatehub.interledger.test?
1. Verify Traefik is running: `docker ps | grep traefik`
2. Check /etc/hosts: `grep mockgatehub /etc/hosts`
3. Verify mockgatehub container is running: `docker ps | grep mockgatehub`
4. Check Traefik logs: `docker compose logs traefik | grep mockgatehub`
