# Backend

Fynbos backend for the control plane. This will start a graphql server on the default port of 8080.
 
## Get started

```shell
go mod tidy
go run main.go
```

### Graphql
We use [gqlgen](https://github.com/99designs/gqlgen) which will read the `./graph/schema.graphql` file and auto-generate the following files:

- `./graph/schema.resolvers.go` resolver stubs are auto-generated here. You will need to go and fill in the implementation. **NB!** The auto-generation won't delete code for resolvers that have been removed from the schema. Instead, it will place it at the bottom of the file for you to review and **manually delete.**
- `./graph/model/models_gen.go` these are the auto-generated Go models that match the Graphql models. **NB** We currently assume that the Graphql and Go models match 1-1. We can in future enable it such that they can be different.
- `./graph/generated/generated.go` these autogenerated functions will be used to make an executable schema and create Graphql handler.

To update the auto-generated files, run
```sh
# run in ./backend
go generate ./...
```

## Deployment
Dependencies:

* [Kustomize](https://kubectl.docs.kubernetes.io/installation/kustomize/binaries/)
* [ko](https://github.com/google/ko)
* [Kubectl](https://kubernetes.io/docs/tasks/tools/)

This uses `ko` to build docker images and push to the appropriate
registry. This will use the `distroless/static:nonroot` image as the 
base image which is stripped of unnecessary packages such as a shell. It
then builds a statically linked go binary on the local machine and 
copies it to the image.

`Kustomize` is then used to generate yaml files to deploy. The Tiltfile
handles using `ko` and `Kustomize` to deploy to the kind cluster. It is
setup to watch the folder and kick off a rebuild.

Local deployment is done using [tilt](../../dev/tilt).
